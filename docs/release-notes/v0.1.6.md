# FileHub Android 0.1.6

## English

Highlights:
- Preserved GPS EXIF in photo and folder sync instead of uploading location-redacted copies.
- Stopped the repeated rename-and-re-upload loop by versioning hashes and reusing the previous remote name.
- Made normal sync incremental and fast: unchanged photos are skipped without per-file hash requests, with a separate full sync for deep verification.
- Made the sync UI truthful with the current action, a log that follows the newest entry, and clear daily/full sync actions.

New:
- Daily photo sync scans only new, modified or failed photos through MediaStore watermarks, and a no-change run finishes with an explicit log line.
- A fast skip reuses a completed photo entry when the local size, mtime and read mode are unchanged and the remote directory still lists the same name and size.
- A full sync action with confirmation re-checks every photo, and folder sync re-verifies every same-size file.
- Folder sync hashes and uploads SAF documents through `MediaStore.setRequireOriginal` when the document maps to a MediaStore item, so photos inside folders keep GPS metadata.
- Sync runs expose the current action: skipped, uploading, verifying, renaming, downloading, deleting or conflict.
- The sync log follows the newest entry after the 200-entry cap and when the log dialog opens.

Improved:
- A no-change incremental scan stops early instead of walking every photo.
- The sync action row places Full sync on the left and the daily action on the right, closer to the thumb.
- Folder sync skips unchanged files without hashing or transferring them and reports "Skipped (already present)".
- Background sync probes server addresses in the configured top-to-bottom order and keeps the first working address.

Fixed:
- Photo sync opens MediaStore items with `ACCESS_MEDIA_LOCATION` and `setRequireOriginal`, preserving GPS EXIF instead of uploading a location-redacted copy.
- Photo sync reuses the previous remote name, or the canonical name when its hash matches, so renamed files no longer grow into `(2)`, `(3)` on every run.
- Legacy photo entries without an original-stream hash are adopted once instead of being renamed or re-uploaded.
- Cached photo and folder hashes are versioned by read mode, so redacted-stream hashes are ignored after location access is granted.
- A denied location permission is shown in both sync screens and logged instead of silently dropping GPS metadata.
- Manual uploads of MediaStore URIs also use the original stream when location access is granted.
- Background sync no longer fails on a stale base URL; a working LAN address is used before a public address.

## 中文

本次亮点：
- 相册和目录同步都保留 GPS EXIF，不再上传位置信息被抹掉的副本。
- 通过哈希版本和复用上次远程路径，终止了反复改名、反复上传的循环。
- 日常同步改为增量和快速跳过，未变更照片不再逐张请求哈希；需要深度核对时用全量同步。
- 同步界面如实显示当前动作，日志自动跟随最新一条，日常/全量同步按钮清晰分开。

新增：
- 相册日常同步通过 MediaStore 水位只扫描新增、修改和失败的照片；没有变化时直接结束并写日志。
- 快速跳过：本地大小、mtime、读取模式都没变，且远端目录里同名文件大小一致时，不再请求远端哈希。
- 全量同步带二次确认，会重新核对所有照片；目录同步会重新校验所有同大小文件。
- 目录同步在 SAF 文档能映射到 MediaStore 时，通过 `setRequireOriginal` 读取和上传，目录里的照片同样保留 GPS。
- 同步运行状态显示当前动作：已存在跳过、上传中、校验中、重名上传、下载中、删除中或冲突。
- 日志达到 200 条上限后仍自动跟随最新一条，打开日志弹窗也会直接停在最新位置。

完善：
- 没有变化的增量扫描会提前结束，不再遍历所有照片。
- 操作行把“全量同步”放左边，“日常同步”放右边，更靠近右手拇指。
- 目录同步对未变更文件跳过哈希和传输，当前动作显示“已存在跳过”。
- 后台同步按配置从上到下探测服务器地址，并使用第一个可用地址。

修复：
- 相册同步使用 `ACCESS_MEDIA_LOCATION` 和 `setRequireOriginal` 打开 MediaStore 原图，保留 GPS EXIF，不再上传脱敏副本。
- 相册同步优先复用上次远程文件名或哈希匹配的原文件名，文件名不会再无限增长成 `(2)`、`(3)`。
- 没有原始流哈希的旧记录只兼容采纳一次，不再重复改名或重传。
- 相册和目录的哈希缓存按读取模式分版本，授予位置权限后不会继续使用脱敏流的旧哈希。
- 位置权限被拒绝时，相册和目录同步都会明确提示并记录日志，不再静默丢失 GPS。
- 手动上传 MediaStore URI 时，在已授权的情况下也使用原始流。
- 后台同步不再因为 `baseUrl` 失效而失败，可用内网地址不会被公网地址抢先。
