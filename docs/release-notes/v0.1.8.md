# FileHub Android 0.1.8

> **Critical fix — upgrade recommended as soon as possible.**
> **重大缺陷修复 —— 建议尽快升级。**

## English

### Critical fix

A background photo/folder sync could start without the UI loading the persisted server list. If a fallback address was used, the sync saved an empty in-memory profile list over the saved servers. The app then showed "no servers", while sync configurations and device tokens were left orphaned.

0.1.8 fixes this at three levels:

- Every profile operation loads the persisted list before touching it.
- The working-address fallback only updates a profile that already exists in the persisted list.
- The profile store refuses accidental empty writes; removing the last server uses an explicit clear path.

If your server list was already cleared, re-add the server and re-create the sync settings. Photos on the phone and files on the server are not affected by this bug.

### New

- Photo and folder sync logs now record every uploaded, skipped, failed and conflicting file, including the reason for skips; folder uploads and downloads are also logged per file. The log keeps the newest 200 entries.
- Each sync run ends with a multi-line briefing: total files/bytes, duration, and uploaded/downloaded/skipped/conflict/failure counts; zero-count lines are omitted.
- The status card uses the same skipped/uploaded/downloaded/failed/conflict counts, hides zero counts, and no longer shows the queued hint while syncing.
- In landscape/wide layouts the status card is compact so the log pane gets more vertical space, and log entries can expand for the briefing.
- Photo sync now keeps MediaStore's full relative path in the remote layout (`DCIM/Camera`, `Pictures/WeiXin`) instead of flattening to the leaf album name; the album picker shows full paths.
- Tablet and landscape server bars show the active server's favicon, with a letter/folder fallback when branding is missing or fails to load.
- Remote directories in the tablet sidebar and landscape roots column show the remote user's avatar, matching the phone root cards.

### Fixed

- Photo name conflicts are explicitly labelled as conflicts.
- Profile decoding failures are logged instead of being silently treated as an empty server list.

**Recommendation: upgrade as soon as possible. This release prevents the saved server list from being cleared by background sync.**

## 中文

### 重大缺陷修复

相册或目录的后台同步可能在 App 未打开时由 WorkManager 拉起，没有加载持久化的服务器列表；切换备用地址时，同步会把空的内存列表写回 DataStore，导致已保存的服务器列表被清空。用户会看到“还没有服务器”，同步配置和设备 token 变成孤立数据。

0.1.8 从三层修复：

- 所有 profile 操作在读写前先加载持久化列表。
- 备用地址切换只更新持久化列表里已经存在的 profile。
- 存储层拒绝意外的空写入；删除最后一个服务器走显式清空路径。

如果服务器列表已经被清空，需要重新添加服务器并重新配置同步。手机照片和服务器上的文件不会受这个 bug 影响。

### 新增

- 相册和目录同步日志逐文件记录上传、跳过、失败和冲突，跳过会带上原因；目录同步的上传和下载也逐文件记录。日志保留最新 200 条。
- 每轮同步结束时写一条多行简报：共计文件数/字节数、耗时、上传/下载/跳过/冲突/失败计数；为 0 的行不显示。
- 状态卡改成同样的 跳过/上传/下载/失败/冲突 计数，为 0 不显示；同步中不再显示“已加入队列”提示。
- 横屏/宽屏下状态卡纵向更紧凑，日志区获得更多高度；日志条目允许多行展示简报。
- 相册同步远端目录保留 MediaStore 完整相对路径（`DCIM/Camera`、`Pictures/WeiXin`），不再压平成叶子相册名；相册选择器也显示完整路径。
- 升级后首次扫描会把旧 entry 的远端路径迁移到新布局；需要先把服务器上旧的相册目录按新路径移好，App 会更新 entry 并跳过已移动的文件。
- 平板和横屏的服务器顶栏显示当前服务器 favicon；品牌图标缺失或加载失败时回退到首字母/文件夹图标。
- 平板侧栏和横屏目录栏的远程目录显示远程用户头像，与手机端目录卡片一致。

### 修复

- 相册同步的重名改名明确标记为“重名冲突”。
- profile 解码失败会记录日志，不再静默当成空列表。

**建议尽快升级。这个版本可以避免已保存的服务器列表被后台同步清空。**
